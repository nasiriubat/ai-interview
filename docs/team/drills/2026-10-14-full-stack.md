# Full-stack drill, 2026-10-14

The production compose stack, run end to end for the first time after the M1 to M3 changes, on one
machine, with throwaway secrets, a scripted model and a mail catcher. Every number below was
produced by the commands named next to it; what was not run is listed at the end.

Related: [chaos drill](2026-10-14-chaos.md), [DEPLOY.md](../../DEPLOY.md#rehearsing-a-deployment),
[Capacity and load](../../DEPLOY.md#capacity-and-load), decisions D-250 to D-259.

## Setup

| Item     | Value                                                                                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Host     | Apple silicon, Docker Desktop VM: 14 CPUs, 8 GB (shared with other projects' containers), linux/arm64                                                                                               |
| Stack    | `deploy/compose.prod.yml` plus `deploy/compose.fake.yml`; project `aidpfull`; Caddy local CA on host ports 18080 and 18443; hostname `aidp.localhost`                                               |
| Env      | `deploy/generate-env.sh` into a scratch directory outside the repository (mode 600, never printed or committed); `CADDY_LOCAL_CERTS=1`; SMTP to the mail catcher; alerts to the fake's webhook sink |
| Model    | `tools/fake-provider` (400 ms + up to 100 ms jitter to first byte, 400 characters/s, 250 ms to first audio byte); embeddings answer 404 like OpenRouter, so analysis clusters lexically             |
| Versions | every release in this record is a git SHA: `5435b6f` (first build) to `b44a1b3` (last); `deploy/versions.env` records the running and the previous                                                  |
| Commands | `deploy/drill/stack.sh` (`up`, `configure`, `run`, `dc`, `down`), `load/run.sh`, `deploy/chaos/run.sh`                                                                                              |

## Findings that were not fixed

F5 was closed by the [second drill](2026-10-14-full-stack-2.md) (D-310, D-311, D-315). F6 is still open (test-only). The rows below are the record as the drill left it.

| F1  | **Voice first word is bounded by the whole reply.** `turn.ts` speaks on the `turn` event, after the model's reply including its metadata block has arrived and been stored; the streamed text is not used. ## What was not run

- The development overlay `docker-compose.fake.yml` was written and described in RUNNING.md but was
  not started: it needs `apps/api/.env`, which this drill deliberately never created.
- No real model provider, no real SMTP relay, no Let's Encrypt (Caddy's local CA), no offsite copy
  (`RCLONE_REMOTE` empty) and so no restore from an offsite copy onto another machine.
- The on-host Whisper model (D-75) was never loaded: transcription went to the fake.
- Embeddings were unsupported by design, so the pgvector path in analysis was not exercised.
- One tenant, one operator, a database of tens of thousands of rows at most.

## Teardown

`deploy/drill/stack.sh down` removed the containers, networks, volumes and images of project
`aidpfull`, and the scratch directory (generated env, raw results) was deleted by hand once the
numbers had been copied into this record and `2026-10-14-load/`. The two tmpfs volumes the
disk-full script made were left behind by a wrong command in that script (compose has no
`volume rm`); they were removed by hand and the script now uses `docker volume rm`. Unused Docker
networks belonging to other projects were left alone: the host had run out of address pools, and the
overlay gives the diagram network a fixed subnet instead.
