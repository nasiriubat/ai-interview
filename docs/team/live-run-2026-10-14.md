# Live pipeline run, 2026-10-14

A real end-to-end run on OpenRouter with cheap models, driven by `pnpm live:run`
(`scripts/live-run`): eight simulated employees through discovery interviews, analysis, promotion
into a requirements session, a nontechnical and a technical owner interview, spec generation,
bundle export and a version diff. About 2.5 USD across five full runs; the final run cost about
55 cents in the ledger and 15 cents in simulators and judge.

The run executed on code from before the M1 merges. The triage column says what the merged tip
already fixes; **the harness must be re-run on the tip** to confirm.

| clustering, analysis_report, spec_turn, spec_generation                 | openai/gpt-4.1-mini                      | 0.40 / 1.60  |

Reasoning-capable models failed: haiku spent hidden output tokens and was cut off at max_tokens in
74% of extraction calls; deepseek-v4-pro was cut off in clustering and produced corrupted spec
markdown. The 400-cent tenant budget held with no overrun.

## What worked

All 8 interviews ended through the engine at 20 to 24 turns, 5 to 44 facts each, cost 1.4 to 2.2
cents per interview. No where-should-AI-go questions, no participant names in the report, all
seven report sections present, anonymous transcripts unreadable by staff by default, delete-my-data
worked, budget enforcement worked, exports returned 200. First token p50 2.7 s (discovery) and
3.9 s (requirements).

Also seen: 29 "turn metadata not parsed" warnings (the model omitted the TURN_META marker so that
turn's state delta is lost), and 82 clusters of one participant each, so k-anonymity was trivially

## Prompt-quality findings

- Formulaic openers: nearly every message begins "Thanks," or "Got it," and often the first name.
  Forbid repeating an acknowledgement and use the name at most once.
- Compound questions: "When was it due, when did it reach you, and what did you do while you
  waited?" Require exactly one interrogative per message; a heuristic found 1 to 4 per interview.
- Requirements interviewer: good defaults with consequences, but 17 of 71 messages had two
  question marks ("question, then confirm default").
- Extraction prompt says "facts already known (do not repeat): N" but passes only a count, so
  duplicates cannot be avoided. Pass a compact list.
- Clustering prompt demands every id echoed; switch to merges over draft ids.
- Spec prompt: state the output language and reject non-ASCII headings (a Chinese-headings run
  occurred with one model, unconfirmed).

## Readiness verdict at the time

Not ready for a pilot: bugs 1 to 4 made finishing and session state unreliable and facts silently
dropped; bug 5 broke analysis at pilot scale. Bugs 1 to 4 are addressed on the tip; 5 to 8 and the
prompt changes are the next work item. Re-run with `pnpm live:run` (about 45 minutes, about 70
cents); environment overrides are documented in `scripts/live-run/README.md`.
