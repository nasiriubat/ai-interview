# Status review, 2026-10-13

An independent assessment of the application against `docs/spec/`, run as six parallel reviews
(spec coverage, security, UI/UX, engineering health, operations, uncommitted tree) plus a full
run of the quality gate and the database-backed suites. Every finding below was read in the
code; the ones marked **verified** were reproduced a second time by hand. Nothing in the repo was
changed by the review itself except this document.

## Verdict in one paragraph

The product does what the spec says a phase-4 product does: an employee can be interviewed by
text, options, recorded voice, live voice or documents; a campaign of interviews becomes a scored
opportunity report; an opportunity or an idea becomes a versioned specification and an agent
bundle; an admin configures all of it as data. The engineering is disciplined (grade B) and the
whole test suite is green, including the 177 database-backed tests that skip silently without
`DATABASE_URL`. What stops it being a product you could hand to a paying tenant tomorrow is not
missing features. It is a short list of operational and privacy gaps: nobody is alerted when
anything fails, "delete my data" leaves the participant's identity behind, every participant
shares one rate-limit bucket, a tenant admin can point the server at internal addresses, the
installed Next.js carries a critical advisory, and Finnish users see mixed-language pages.

## Findings that gate a pilot

Ordered by what a first customer would hit first. Severity is the reviewers' consensus.

1. **Verified. Every anonymous participant shares one rate-limit bucket.** The web proxy
   (`apps/web/src/lib/api/proxy.ts`) forwards no client address, so the API keys anonymous
   callers by the web container's IP. Link open is two requests against a 30-per-minute bucket,
   so about 15 arrivals per minute across the whole deployment produce 429s. The same bucket lets
   one attacker lock out email-code sign-in platform-wide. Fix: forward `x-forwarded-for`, set
   `trustProxy` to the hop count, add an e2e test with two addresses.
2. **Verified. "Delete my data" and retention do not delete the participant.**
   `deleteSessionOps` in `packages/core/src/privacy/retention.ts` removes messages, events,
   facts and attachments and blanks the session, but never touches `Participant` (name, email,
   role, department, token hash), `Invitation` (plaintext email), `CampaignEmailHash`,
   `EmailCode` or `SpecVersion`. This contradicts spec 11 and the consent text. The participant
   token also stays valid after deletion and the summary can still be written.
3. **No alerting of any kind.** Budget warnings, budget exhaustion, job dead-letters, backup
   failure and disk pressure all end in `log.warn`. The participant is told "The organizer has
   been notified" (`turn-runner.ts`) and nobody is. `cost.onBudgetExceeded: "downgrade"` is a
   catalog key that nothing reads. Fix: an `AlertPort` in `packages/core` with email to the
   operator and an optional webhook, wired to those five events; correct the participant string;
   remove or implement `downgrade`.
4. **SSRF through admin-configured provider URLs.** `baseUrl` is any URL; the adapter follows
   redirects and echoes the first 500 bytes of error bodies back to the admin through
   `/providers/:id/test` and `/models`. On a VPS that reaches cloud metadata and every compose
   service. Fix: resolve and reject private, loopback and link-local ranges on every connect,
   require https for tenant providers, stop echoing bodies. Apply the same filter to the SMTP URL.
5. **Verified. Dependency advisories.** Installed Next.js 16.3.4 is below the 16.3.6 critical
   fix and the 16.3.8 SSRF fix. Nodemailer 7.x carries about ten advisories. OpenTelemetry,
   fastify and sharp have highs. CI has no audit or Dependabot step, which spec 11 requires.
6. **Unbounded body buffering in the proxy.** `await req.arrayBuffer()` on every non-GET request,
   with no Caddy `request_body` limit and no content-length check, against a 768 MB web
   container. Fix: Caddy body limits per path, content-length rejection, streaming forward.
7. **Verified. Server-rendered pages ignore the Finnish locale.** The per-request locale store
   is filled by the root layout; 33 pages read strings without awaiting it, so page headers,
   table headers and status screens render English while client islands render Finnish.
   Reproduced three times with a `lang=fi` cookie. Fix: await `requestLocale()` at the top of
   each page, or resolve `t` through the request on the server.
8. **No outbound timeouts on the OpenAI-compatible path.** Bare `fetch` with no `AbortSignal`;
   the 120 s turn lock expires while the hung request keeps the connection. Fix:
   `AbortSignal.timeout`, a first-token deadline, explicit Anthropic timeout and retries.
9. **Tenant suspension is not enforced.** The operator can set `status: "suspended"`; nothing
   checks it for staff sign-in or participant link open.
10. **Worker healthcheck is tautological** (`kill -0 1`). A worker whose pg-boss has stopped
    reports healthy forever. Fix: a heartbeat file refreshed only when pg-boss answers.

## Findings that are owed to the spec, not to a pilot

Security and privacy:

- **Verified.** RLS covers 13 tables but not `Message`, `SessionEvent`, `Analysis`,
  `Opportunity`, `Report`, `Invitation`, `CampaignEmailHash`, `EmailCode`, `Setting`. These
  have no `companyId`, so the preflight cannot see them and the "second fence" is absent for
  transcripts. Add a denormalised `companyId` and a policy, or `EXISTS` policies.
- k-anonymity gates quotes, roles and departments but not `evidence` snippets, which carry
  verbatim quotes for clusters of one (`packages/ai/src/analysis/pipeline.ts`).
- The email hash uses the platform key with no per-campaign salt; `Invitation.openedAt` equals
  the session's `createdAt`, which lets a small anonymous campaign be de-anonymised by timing.
- Staff identity is resolved with `findFirst` by email across tenants; an admin of tenant A can
  create a user with tenant B's address and capture their sign-in.
- Transcript visibility "admins" is not enforced for members; the session response spreads the
  campaign row including the link hash and invitations.
- Provider custom `headers` are stored plaintext, returned to the browser and written to the
  audit log.
- No participant data export, no sub-processor list, no key rotation path, no user disable or
  delete, prompt injection has no structural delimiting and the report renderer allows images.
- Uploads: 200 MB buffered in memory before the tenant limit is checked, no magic-byte check,
  no per-session or per-tenant quota, no decompression cap for DOCX and XLSX.

Engineering:

- **Data loss path.** `session.extract` advances `lastExtractedSeq` and saves state per batch,
  but the worker writes `Fact` rows only after all batches return. A crash between the two
  loses facts permanently. Make it one transaction.
- Retention swallows a failed `deletePrefix` and the sweep never revisits deleted sessions, so
  orphaned audio is never retried. The code comment says otherwise.
- The provider "test connection" calls the adapter directly, bypassing `ModelCaller`, routing,
  budget and ledger (rule 2 of `AGENTS.md`).
- The SSE turn stream emits no `error` event for failures inside the `for await` loop.
- The extraction job hardcodes `extractorVersion: "extraction@1"`; interviewer prompts v1 to v3
  are dead files; nothing pins a prompt body hash to its version.
- Evals are two fixtures of 8 and 9 answers. NFR-06 asks for 60-turn transcripts, fact recall
  after summary, issue-detection precision and extraction accuracy, with merges blocked on
  regression. The live-model eval does not exist.
- Ledger under-bills voice: `transcribe` records zero usage, abandoned streams record zero,
  TTS is modelled as output tokens.
- 11 of 16 API modules keep tenant-owned queries in `routes.ts` rather than a service, so rule 4
  is enforced by review rather than by structure.
- Worker tests are structural only; no handler is exercised for retry or idempotency.
  `email.send` is not idempotent.

Operations:

- No job admin or dead-letter view (NFR-09); `queueStats()` has no callers. No `expireInSeconds`
  per job, so a long analysis is redelivered after 15 minutes and runs twice.
- Backups are on-host only and unverified by automation. Rollback needs a rebuild on the VPS.
- Worker has no OpenTelemetry; API logs carry no tenant or session id; `/stats` has averages
  only, so NFR-01 p95 cannot be measured.
- `docs/DEPLOY.md` names purposes that do not exist (`summarize`, `analysis`, `report`) and has
  a stale object-storage paragraph; spec 12 references an `infra/` directory that does not exist.

Usability and accessibility:

- No confirmation on revoke invitation, clear route override, suspend tenant, change role, or
  the participant's "I'm done", against spec 19.
- Long forms (template editor, campaign, requirements) put validation errors at the top with no
  focus move or scroll; the submit button appears to do nothing.
- No "what changed" panel for the settings catalog; `SettingDef` has no `since` field. Settings
  edits are lost silently on category change; no dirty guard anywhere in the web app.
- Campaign and template settings are reachable only through the global settings scope picker;
  a campaign cannot be edited after creation.
- Resume recap not implemented; its strings exist unused. Live voice is a composer panel, not
  the spec's full-screen mode. "Skip" and "I'm done" appear in the transcript as things the
  participant said.
- 28 admin call sites render raw enum identifiers or `humanize(key)` instead of translated
  labels. Currency is hardcoded EUR.
- WCAG: control boundaries at about 1.2:1 to 1.8:1 against 3:1 required; button focus ring at
  about 1.6:1; streaming bubble inside `aria-live` plus `role="log"` double-announces;
  `ModeSwitch` radios without roving tabindex; `Alert` always `role="alert"`; `animate-*`
  transitions unguarded for reduced motion. The 404 page sends participants to the staff
  sign-in.

## The uncommitted tree

196 files, about 4,900 insertions, is seven coherent workstreams, each with a decision row
(D-74 to D-80), spec text and tests: design-system refresh, server-side list queries with
migration 0012, on-server Whisper, streaming captions and live-voice admin, browser read-aloud,
one server image with compiled seeds, and docs. No debug code, no dangling imports, no
binaries. Three things to fix before committing: `apps/api/.env.example` lacks
`OPENAI_BASE_URL`, `MODEL_CACHE_DIR` and `SPEECH_MODEL_IDLE_MINUTES`; four list pages
(campaign sessions, budgets, provider prices twice) have API search but no `ListToolbar`, so
spec 19 overstates what shipped; `DEPLOY.md` should say the web image build needs egress to
Google Fonts. Suggested split, in order: bodiless-POST hook and lazy OTel; list queries; Whisper;
streaming captions; read-aloud; build changes; design system. `phase4-files.png` in the repo root
is already tracked and should go in its own commit if unwanted.

## Improvement plan

Effort is a working estimate for one engineer or agent, in days.

### Tier 0: land what exists (1 day)

1. Fix the three pre-commit items above, split and commit the seven workstreams, push, confirm
   CI green.

### Tier 1: pilot blockers (6 to 8 days)

Everything in "Findings that gate a pilot", in this order, each with a test:

1. Rate-limit identity through the proxy (0.5). 2. Deletion scope: participant, invitation,
   email hash, codes, spec versions, reject writes to deleted sessions (1). 3. `AlertPort` and the
   five alert sources, fix the participant string, remove `downgrade` (1.5). 4. SSRF guard for
   provider and SMTP URLs, stop echoing bodies (1). 5. Dependency upgrades: Next 16.3.8+,
   nodemailer 9+, OpenTelemetry, fastify; add `pnpm audit` and Dependabot to CI (1). 6. Proxy
   body limits (0.5). 7. Server locale resolution (0.5). 8. Outbound timeouts (0.5). 9. Tenant
   suspension (0.5). 10. Worker heartbeat healthcheck (0.5).

Also in this tier because they are cheap and change outcomes: the `session.extract`
transaction, retention orphan retry, SSE error event, `expireInSeconds` per job.

### Tier 2: privacy and tenancy debt (5 to 7 days)

RLS on the remaining nine tables with preflight coverage; k-anonymity on evidence; per-campaign
salt and coarsened `openedAt`; globally unique staff email or tenant in the JWT; transcript
visibility per role and a session DTO; encrypted provider headers; upload streaming with early
cap, magic bytes, quotas and decompression limits; prompt delimiting and image stripping in the
report renderer; user disable and delete; participant data export.

### Tier 3: finish phase 5 for a solo operator (6 to 8 days)

Job admin page with dead-letter retry; worker OpenTelemetry and tenant ids in logs; p95 and
voice metrics in `/stats`; offsite backup sidecar gated on `RCLONE_REMOTE` and a weekly
automated scratch restore; image tags for rebuild-free rollback; prompt administration route and
UI over the existing `PromptVersion` table; template rollback; the settings "what changed"
panel; notifications for completion and analysis-ready.

### Tier 4: spec debt in phases 1 to 4 (5 to 7 days)

PDF export for report and spec (Kroki is already in compose, unused); cluster merge, split and
rename; department comparison; resume recap via `resume_summary`; admin-visible hostility flag;
deletion confirmation email; the UX list: confirmations, form feedback, settings links from
objects, campaign edit, enum labels, WCAG contrast and focus, live-region fix, 404 page.

### Tier 5: make the evals real (3 to 5 days)

Prompt-hash-to-version pinning test; 60-turn fixtures with difficult-participant variants;
fact-recall-after-summary, issue-detection precision and extraction accuracy metrics; the
`eval:live` harness behind an API key; worker handler tests with in-memory stores.

Tiers 0 to 2 are what "safe for a first pilot customer" means. Tiers 3 to 5 are what the spec
already promised. Phases 6 to 8 are not costed here.
