# End-to-end simulation before hand-over, 2026-10-15

A real-life run of the whole product in a browser, the way a client's installer, administrator and
staff would meet it, on the day before the deployment is handed over. Everything was done through
the web UI with Playwright (Chromium, headless), except where noted. Fixes were made as issues were
found, each with a test; decisions are D-460 to D-469 in `docs/discovery/decisions.md`.

The company, its people and every answer are fictional: "Kestrel Health", a regional clinic
network, with simulated employees from `tools/live-run/src/demo-personas.ts` played by a low-cost
model (`qwen/qwen3-30b-a3b-instruct-2507`). Nothing here is a customer or a measurement of real people.

## How it ran

| Part               | What                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stack              | Production builds: `apps/api/dist/server.js`, `apps/worker/dist/main.js`, the Next standalone server (`apps/web/.next/standalone`, static and public copied beside it as the Dockerfile does), all with `NODE_ENV=production`; own database `ai_discovery_sim`; Mailpit as the relay; web on :3300, API on :4300                                                      |
| Install            | `prisma migrate deploy`, `pnpm --filter @aidp/db bootstrap` with the OpenRouter key read from the root `.env` at runtime (never printed); local Whisper for transcription                                                                                                                                                                                             |
| Routes             | Set to low-cost models through the product's own operator routes and price table (the live-run harness's `configureRouting`): interviewer `anthropic/claude-haiku-5.5`, extraction and summaries `mistralai/mistral-small-3.2-24b-instruct`, analysis and specification `openai/gpt-4.1-mini`; tenant budget $2.50                                                    |
| Operator and admin | Signed in from the emailed link (read from Mailpit's API); product name "Kestrel Discovery" under Settings, Branding, platform level; SMTP form test send to Mailpit; a campaign from the discovery template; welcome text edited; two colleagues invited by email; a user added                                                                                      |
| Participants       | Six discovery interviews through the share link and two personal invitation links: desktop 1440 and phone 390 contexts, email code from Mailpit, details, consent, typed answers from the persona simulator, answer options when offered, one pause and resume, one recorded voice answer through Chromium's fake microphone (a WAV made with `say`), finish, summary |
| Analysis           | Automatic run at the threshold (5), a merge of two opportunities (re-analysis), a sixth interview and a manual run: four versions; results, opportunities, departments (two departments of three), report, PDF export                                                                                                                                                 |
| Requirements       | One from an idea (30 owner turns from the simulator, the read-back answered with two corrections, finished), one promoted from a discovery opportunity (16 turns, read-back corrected); three specification versions, compared; PDF, Markdown and agent-bundle (zip) downloaded                                                                                       |
| Marketing          | `tools/marketing/capture.ts` against the same stack; 30 screenshots, each looked at                                                                                                                                                                                                                                                                                   |

## Seen and not fixed (still weak)

- **Requirement capture on the opportunity interview.** After 16 owner turns the read-back listed
  one requirement ("A nurse can log a patient's text confirmation"); the owner had to say what was
  missing, and the interviewer then recorded it. The idea interview captured 22 to 26. Claims C7
  already says not to quote counts; this run is one more reason. Worth a look at how the hand-off
  brief and `spec_field` capture interact.
- **Hours per week stay large** after the de-duplication (191 for six people): the simulated people
  are cooperative and generous with numbers, and the opportunity grouping sums people's time across
  overlapping opportunities. Present it as "self-reported, described across the opportunities"
  (which the page already says), never as savings.
- **Content-Security-Policy console errors on pages with diagrams** ("Applying inline style
  violates ... style-src"). The diagrams render (their `<style>` carries the nonce); the errors come
  from a script chunk applying styles. No visible effect; not investigated.
- **A React hydration warning (#418)** appeared once in a phone participant context and could not be
  reproduced on the arrival, landing or sign-in pages.
- **Answers recorded before D-463 keep option keys** ("onprem", "team") in the idea interview's
  context; only new answers are labelled.
- The SMTP test against a relay on the same host needs `EGRESS_ALLOW_HOSTS=127.0.0.1` (or the relay's
  name); the message now says so. A real relay on the internet needs nothing.
- Live voice (talking, not recording) was not exercised: it ships off and needs a TTS route.
- GitHub push was not exercised (claims C6 stays Partial).
