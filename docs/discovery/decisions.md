| D-100 | `session.extract` commits each batch in one transaction: the Fact rows, a patch of the session state's `facts` and `lastExtractedSeq`, and the `facts_extracted` event, behind a compare-and-set on the cursor. Rows are keyed `(sessionId, batchEndSeq, ordinal)` (migration 0015), so a replayed batch writes nothing. A `stale` commit (another run got there first, or the session was deleted) ends the run without error, because the run that holds the cursor is itself retried if it fails                                                                                                                                                                         | DECIDED | engineering M1, correctness half | 2026-10-13 |
| D-101 | A prompt's version is read from the prompt object (`promptVersionTag`) and never typed: ESLint rejects a `key@N` literal outside `prompts/`. `interviewer.v1` to `v3` were unregistered and are deleted (git has them). Every shipped prompt body is pinned to its version by sha256 in `packages/ai/test/engine/prompt-pins.json`; editing a body without bumping the version fails the pin test, and `UPDATE_PROMPT_PINS=1` re-pins deliberately                                                                                                                                                                                                                          | DECIDED | engineering M1, correctness half | 2026-10-13 |
| D-102 | The two background cursors only grow. A whole-state write from the turn is reconciled against the stored document under a row lock (larger `lastExtractedSeq` and `summaryUpToSeq` win, extracted facts are kept), and the summary job patches only its own keys through `commitSummary`. Both jobs are published by the same turn and finish while the participant answers the next question, so a stale turn writing its snapshot back used to rewind them and duplicate facts                                                                                                                                                                                            | DECIDED | engineering M1, correctness half | 2026-10-13 |
| D-103 | Retention orphan recovery is a GC pass at the end of each tenant sweep, not a retry job: it lists the tenant's session directories (`StoragePort.listPrefixes`) and removes those with no live session, past a one-hour grace window, capped at 500 per sweep, with a `privacy.storage_gc` audit row. A retry job would need an outbox to remember a prefix that no row remembers. Expired recordings delete the file first and the row only on success, so the row is the retry record. `privacy.delete-session` throws on a failed file delete so the queue retries it                                                                                                    | DECIDED | engineering M1, correctness half | 2026-10-13 |
| D-104 | A caller-supplied `AbortSignal` rides `CallRequest.signal` to the adapter (`fetch` and the Anthropic SDK). The turn lock is renewed every 30 s and expires after 90 s, and a turn that loses its lock aborts. `tenantTransaction` now flips to in-transaction before sending the tenant setting (it used to run on another connection, so row-level security hid every row inside the transaction) | DECIDED | engineering M1, correctness half | 2026-10-13 |
